# Fairness and currency

## Currency

- **Unit:** ByteBits credits (integer).
- **Source of truth:** Supabase `players.balance`.
- **Starting balance:** 1000 credits on first `/balance` or bet.
- **Faucet:** `/daily` +500 credits every 24 hours.
- **Not convertible** to cryptocurrency or fiat. No backed or redeemable value.

## House edge (paytable v1)

Target **theoretical return to player (RTP) ≈ 95%** (4–5% house edge) on even-chance style games. Exact multipliers live in `src/paytables/v1.ts` and are shown via `/paytable`.

| Game | Player edge model |
|------|-------------------|
| Coinflip | 50% win chance × published multiplier |
| Dice | 1/6 win chance × published multiplier |
| Mines | Per-reveal multiplier curve scaled to ~95% RTP at cash-out |
| Roulette | European wheel (37 pockets); standard payout table |

## Provably fair

1. **Server seed** — generated by the bot; **hash** published while active.
2. **Client seed** — player-controlled via `/seed` (default: Discord user id).
3. **Nonce** — increments by one on each settled wager (atomic in DB).
4. **Outcome** — HMAC-SHA256(server_seed, `client_seed:nonce:cursor`) → deterministic floats/integers.
5. **Verification** — `/verify` replays outcome from bet metadata after server seed is revealed.

### Seed rotation

When the server seed is rotated, the previous seed is revealed so players can verify past bets. P1 adds admin rotation; P0 stores commitments in `fairness_commitments`.

Game-specific fields (pick, roll, mine positions, roulette pocket) are included alongside fairness fields.
